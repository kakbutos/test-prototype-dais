# Публикация прототипов

Прочитай `docs/PUBLISHING.md`. Если пользователь просит поделиться результатом, но формат ещё не выбран, уточни HTML или Pages по `AGENTS.md`. Явный запрос ссылки Pages уже задаёт выбор. Запрос публикации разрешает необходимые commit/push/deploy в установленный репозиторий; создание нового публичного репозитория требует известных владельца и аудитории. Не меняй видимость существующего репозитория без запроса.

1. Проверь `git remote -v`, ветку и status. Убедись, что origin указывает на предназначенный пользователю репозиторий. Не отправляй макеты в исходный шаблон вместо своей копии.
2. Выполни `npm run build`, просмотри diff. Браузерных автотестов нет, устанавливать их для публикации не нужно. Тесты служебных скриптов и диагностика MCP выполняются в Actions; локально запускай их при изменении соответствующих частей или диагностике ошибки.
3. С gh проверь auth status и используй `npm run publish:check`, при первой настройке — `npm run publish:setup`. Без gh настрой Pages в браузере: Settings → Pages → Source → GitHub Actions. Git может авторизоваться через имеющийся credential helper; вход/2FA завершает пользователь. Не требуй установки gh, не запрашивай секреты в чате.
4. Добавь только относящиеся к задаче файлы; исключи конфиги MCP, зависимости и результаты сборки. Создай commit и push. Публикуется main; для другой ветки соблюдай процесс PR, без force-push и несогласованного слияния.
5. С gh выполни `npm run publish:wait`; без gh проверь запуск для отправленного commit во вкладке Actions. Если доступа к результату нет, дай ссылку на запуск и явно сообщи, что deploy не подтверждён. После двух неуспешных исправлений одной причины сообщи блокер.
6. Верни фактический URL Pages с `#/<slug>` и статус публикации. Применяй соразмерную браузерную проверку из `AGENTS.md`; не повторяй уже выполненный просмотр без новой причины. После deploy проверь доступность страницы, а при изменениях маршрутов/ресурсов — их работу на опубликованном адресе. Успешные push/build сами по себе не доказывают ни deploy, ни работу всех сценариев.

Изменения посетителя живут только в памяти. Для общего начального состояния измени данные в исходниках и опубликуй заново.
