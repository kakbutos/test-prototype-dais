# Автономный HTML одного экрана

Прочитай `docs/HTML_EXPORT.md`. Явный запрос HTML уже задаёт формат результата. Используй прототип, указанный пользователем или однозначно определённый текущей работой. Если вариантов несколько и целевой неизвестен, уточни только его. Не экспортируй всю галерею и не выбирай первый вариант молча.

1. Выполни `npm run export:html -- <slug>`: TypeScript, сборка отдельной точки входа выбранного экрана и проверка единственного файла `dist-html/<slug>/index.html`. Если в проекте всего один вариант, slug можно опустить. Другие экраны и оболочка галереи не подключаются; общие модули, реально импортированные выбранным экраном, входят в его зависимости. Исходные PNG из `.references` в приложение импортировать запрещено.
2. Встрой необходимые экрану ресурсы через импорты. public/ не копируется в автономную сборку; не используй внешние пути или сеть для обязательных ресурсов автономного экрана. Шрифты SB Sans Text/Display встроены. Не выдавай папку/ZIP вместо одного HTML. Экспорт содержит начальные данные из кода, а не состояние открытой сессии.
3. Браузерные автотесты не входят в шаблон. При изменении упаковки/ресурсов, проблеме открытия или запросе проверки открой именно итоговый файл через file://, проверь экран без галереи и его действия. Для проверки автономности отключи сеть доступными средствами. Не заменяй это dev-сервером и не устанавливай тестовый фреймворк. Если отключение сети или браузер недоступны, сообщи об этом. Повторять весь просмотр уже проверенного экрана при неизменной упаковке не нужно.
4. Передай путь к HTML, название выбранного прототипа, размер и фактические результаты проверок. Размер зависит от компонентов, шрифтов и ресурсов экрана; не обещай маленький файл без измерения. Получатель скачивает и открывает файл в браузере. Экспорт не требует commit/push.

После изменения исходников повтори экспорт выбранного варианта. Результаты других вариантов в dist-html сохраняются, но каждый передаётся отдельным HTML.
