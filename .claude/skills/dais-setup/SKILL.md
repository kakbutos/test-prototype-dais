# Подготовка Dais

Прочитай `docs/GETTING_STARTED.md`. Работай из папки с package.json `dais-prototypes-template`. До подготовки способа передачи результата используй правило выбора из `AGENTS.md`: HTML-файл, ссылка на GitHub Pages через Actions или пока локально. Учитывай уже данную пользователем информацию, не повторяй вопрос.

Для всех вариантов нужны Node/npm, копия проекта и ИИ-клиент. HTML и локальная работа не требуют Git или GitHub-входа. Для Pages нужны свой репозиторий, Git и авторизация; gh — дополнительный способ настройки, а не обязательная зависимость.

Определи ОС и оболочку. Проверь `node --version`, `npm --version`; Git/gh проверяй по выбранному сценарию. Node: 22.14+ из ветки 22 либо 24+. Не заменяй рабочие установки. На Windows при блокировке npm.ps1 используй npm.cmd или cmd. Помогай пройти недостающие установщики по руководству и перепроверяй результат; при недоступных правах назови точный блокер. Не отключай проверку сертификатов.

Для Pages следуй `docs/PUBLISHING.md`: с gh доступны publish:*; без gh настройка Pages выполняется в браузере, а отправка — обычным Git. Проверяй адрес назначения, аккаунт и локальные имя/email. Не меняй глобальные настройки или активный аккаунт без причины; пароль, токен и одноразовые коды не запрашивай в чате. Подготовка сама по себе не разрешает публикацию.

1. Выполни `npm run setup`: npm ci, проектные конфиги MCP, синхронизация навыков, диагностика и реальные MCP-вызовы. Исходники Dais/Plasma/Glide скачивать не требуется.
2. При проблемах используй `npm run doctor` и `npm run mcp:check`. Не обходи peer-конфликты через force/legacy-peer-deps и не переключай пакеты на latest.
3. После setup один раз перезапусти/попроси перезапустить клиент в папке проекта: это нужно для подхвата и MCP, и навыков. Пройди штатную процедуру доверия проекту. Навыки, не обнаруженные автоматически, читай напрямую из `.agents/skills`; это штатный способ и до перезапуска.
4. Проверь доступный агенту `dais-ui` вызов `get_component` для `TableCanvas`. Раздельно сообщи: сервер проверен через mcp:check; инструмент вызван из текущей сессии или недоступен; навык обнаружен автоматически либо прочитан как файл. Smoke-тест сервера не доказывает подключение клиента. Если инструмента нет, продолжай по установленным типам и примерам согласно dais-prototype, не называя подключение подтверждённым.
5. Запусти `npm run dev` и дай фактический локальный адрес. Назови выполненные и непроверенные шаги. Браузерные автотесты для подготовки не нужны.

Повторная подготовка сохраняет `src/prototypes`, другие MCP и настройки. Конфиги исключены из git. Для передачи результата используй dais-export-html или dais-publish согласно запросу.
