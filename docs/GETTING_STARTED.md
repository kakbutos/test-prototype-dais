# Первый запуск: от установки до HTML-файла или ссылки

Инструкция для дизайнера без опыта работы с терминалом. Пройдите подготовку один раз; дальше вы будете открывать свою папку проекта и описывать макеты агенту.

## Выберите способ передачи

- **HTML-файл:** скачайте и распакуйте шаблон через Code → Download ZIP или откройте готовую папку проекта. Нужны Node.js/npm и агент. Шаги 4–6 про GitHub пропустите и переходите к шагу 7. Git и gh не требуются; результат — один HTML, не архив.
- **Ссылка на GitHub Pages через Actions:** нужны своя копия репозитория, Git и авторизация GitHub. gh можно использовать для настройки, но он необязателен.
- **Пока только локально:** такая же подготовка, как для HTML; способ передачи выберете позже.

Агент уточнит выбор, если вы его ещё не указали. Он не спрашивает повторно при каждой правке.

Если агент уже установлен и умеет работать с файлами, можно сразу передать ему ссылку на этот документ и написать:

> Помоги подготовить мой компьютер для Dais-прототипов по этой инструкции. Сначала проверь, что уже установлено. Делай доступные шаги сам, а установщики и вход в аккаунты проводи со мной по одному шагу. После каждого шага проверяй результат. Если я ещё не выбрал результат, уточни: HTML-файл, ссылка на GitHub Pages или пока локально. Пока ничего не публикуй.

## 1. Что нужно установить

| Программа | Для чего | Когда нужна |
| --- | --- | --- |
| ИИ-агент | Создаёт макеты по описанию и PNG, меняет файлы | Для работы с ИИ |
| Node.js вместе с npm | Запускает приложение и устанавливает его библиотеки | Для локального запуска |
| Git | Скачивает проект и отправляет изменения | Для работы со своей копией на GitHub |
| GitHub CLI (`gh`) | Авторизация и настройка публикации из агента | Необязателен; упрощает настройку Pages |

Вход в ИИ-клиент нужен независимо от формата результата. Для Pages дополнительно нужен доступ к GitHub в браузере и авторизация Git на компьютере; gh — один из способов её настройки. При использовании gh он может настроить авторизацию Git; без gh используйте имеющийся Git credential helper. Для HTML вход в GitHub не нужен. Подписка/доступ к ИИ-клиенту не включены в этот шаблон. Dais, React, MCP и остальные npm-пакеты вручную устанавливать не нужно — их поставит `npm run setup`.

## 2. Подготовьте компьютер

Сначала проверьте установленные программы. Не переустанавливайте то, что уже работает.

**macOS:** нажмите `⌘ Space`, введите «Терминал» или `Terminal` и откройте приложение.

**Windows:** откройте «Пуск», введите `cmd` и откройте «Командная строка». В этом руководстве для Windows используем именно её, чтобы не упираться в ограничения запуска PowerShell-скриптов.

Проверьте Node/npm. Git нужен для Pages; gh проверяйте, только если планируете им пользоваться:

```sh
node --version
npm --version
git --version
gh --version
```

Если выводится номер версии — программа найдена. Если нужная для вашего сценария программа не найдена — установите её по шагам ниже. Отсутствие необязательных Git/gh не блокирует HTML. Для Node подходит 22.14+ из ветки 22 либо 24+. Для новой установки в этом руководстве выбирайте актуальную версию **22.x**: проект проверялся на этой ветке. Уже установленный подходящий Node менять не нужно.

### На macOS

1. **Node.js:** откройте [официальную страницу загрузки](https://nodejs.org/en/download), выберите версию 22.x, macOS и установщик `.pkg`. Откройте скачанный файл и пройдите установку. npm входит в комплект.
2. **Git, для Pages:** если его нет, в Терминале выполните `xcode-select --install`. В системном окне согласитесь на установку Command Line Tools и дождитесь окончания. Полный Xcode для проекта не требуется. Это [официально описанный способ установки Git](https://git-scm.com/install/mac).
3. **GitHub CLI, по желанию для Pages:** если Homebrew уже установлен, выполните `brew install gh`. Если Homebrew отсутствует, откройте [brew.sh](https://brew.sh/) и используйте указанный там установщик для macOS. Завершите его шаги настройки терминала; если он выводит команды в разделе Next steps, выполните их. Откройте новый Терминал, проверьте `brew --version`, затем выполните `brew install gh`. [Инструкция GitHub CLI](https://cli.github.com/).
4. Закройте и заново откройте терминал и ИИ-клиент. Проверьте версии установленных программ.

Если установщик требует недоступные права, обратитесь к администратору со списком нужных программ. Если Homebrew не поддерживает вашу версию macOS, используйте согласованный с ИТ способ установки GitHub CLI. Пароль macOS вводится в системное окно или терминал установщика, не в чат; при вводе пароля в терминале символы могут не отображаться.

### На Windows

1. **Node.js:** на [официальной странице](https://nodejs.org/en/download) выберите версию 22.x, Windows и установщик `.msi` для архитектуры вашего ПК. Запустите его, оставьте установку npm и добавление в PATH включёнными. Архитектура указана в «Параметры → Система → О системе → Тип системы»: обычно x64, на ARM-компьютерах — ARM64.
2. **Git, для Pages:** скачайте установщик с [Git for Windows](https://git-scm.com/install/windows) для своей архитектуры. В шаге выбора PATH оставьте вариант использования Git из командной строки и сторонних программ; остальные параметры можно оставить по умолчанию.
3. **GitHub CLI, по желанию для Pages:** откройте [cli.github.com](https://cli.github.com/), выберите **Windows → Download MSI**, скачайте и запустите установщик для своей архитектуры.
4. Закройте и заново откройте командную строку и ИИ-клиент. Проверьте версии установленных программ.

Если установка недоступна, обратитесь к администратору со списком нужных программ. Менять политики безопасности Windows для этого руководства не требуется.

## 3. Установите один ИИ-клиент и войдите в него

Если клиент уже работает, пропустите его установку. Используйте одобренный вашей командой вариант с доступом к локальным файлам и терминалу:

- **Codex:** пройдите [официальный Quickstart](https://learn.chatgpt.com/docs/quickstart) для настольного приложения или расширения. Выполните вход через предлагаемый клиентом браузерный процесс; [описание авторизации](https://learn.chatgpt.com/docs/auth).
- **Claude Code:** выберите способ установки для своей ОС в [официальной инструкции](https://code.claude.com/docs/en/setup), затем завершите предлагаемый клиентом вход.
- **GigaCode:** установите поддерживаемую IDE и плагин по [инструкции GitVerse для VS Code](https://gitverse.ru/docs/ai/ai-assistant-gigacode/gigacode-for-vscode/) либо используйте настроенный вашей командой CLI. Завершите предусмотренную вашим вариантом клиента авторизацию.

Устанавливать все три клиента не нужно. Сначала убедитесь, что выбранный клиент отвечает в чате. Для работы по PNG ему также нужна поддержка изображений. Форматы конфигов подготовлены для нескольких клиентов, но полный первый запуск в каждом продукте отдельно не проверялся — см. [границы проверки](VALIDATION.md).

## 4. Для Pages: создайте свою копию шаблона

1. Откройте [GitHub](https://github.com/), войдите или зарегистрируйтесь. При регистрации подтвердите email.
2. Откройте [dais-prototypes-template](https://github.com/kakbutos/dais-prototypes-template).
3. Нажмите **Use this template → Create a new repository**.
4. В Owner выберите свой аккаунт; в Repository name введите, например, `my-prototypes`.
5. Для этого сценария с публичными вымышленными демоданными выберите Public и нажмите **Create repository from template**. Видимость репозитория выберите под свою аудиторию; доступность Pages зависит от тарифа и настроек.

[Официальная инструкция с картинками](https://docs.github.com/en/repositories/creating-and-managing-repositories/creating-a-repository-from-a-template). Готовый результат: страница `github.com/ВАШ_ЛОГИН/my-prototypes`. Это ваша отдельная копия для макетов.

## 5. Для Pages: настройте авторизацию Git

**Без gh:** используйте имеющийся Git credential helper. Git for Windows обычно включает Git Credential Manager: при первом обращении, требующем входа, он может открыть браузер. Завершите вход в нужный аккаунт и 2FA. Если helper отсутствует или вход не работает, попросите агента проверить доступные способы авторизации. Имя/email в git config не являются авторизацией. [Документация GitHub](https://docs.github.com/en/get-started/git-basics/caching-your-github-credentials-in-git).

**С gh:** в терминале выполните:

```sh
gh auth login --hostname github.com --git-protocol https --web
```

Команда покажет дальнейшие действия. Если появился одноразовый код, введите его на странице GitHub, открытой этой командой. Войдите под аккаунтом, которому принадлежит ваша копия, и подтвердите авторизацию GitHub CLI. Вход и подтверждение второго фактора выполняете вы, не агент.

Затем выполните по очереди:

```sh
gh auth setup-git --hostname github.com
gh auth status
```

Первая команда подключает авторизацию GitHub CLI к Git для github.com. Вторая должна показать ваш аккаунт как активный. Пароли, токены и одноразовые коды не отправляйте в чат. [Вход через браузер](https://cli.github.com/manual/gh_auth_login), [подключение авторизации к Git](https://cli.github.com/manual/gh_auth_setup-git).

## 6. Для Pages: склонируйте свою копию и откройте в агенте

На странице **своего** репозитория нажмите **Code → HTTPS → Copy**. В терминале введите `git clone`, пробел и вставьте скопированный адрес. Например, заменив `YOUR_LOGIN` на свой логин:

```sh
git clone https://github.com/YOUR_LOGIN/my-prototypes.git
cd my-prototypes
git remote -v
```

Команда clone создаст папку в текущем расположении терминала; при обычном запуске это, как правило, домашняя папка пользователя. Чтобы увидеть полный путь, на macOS выполните `pwd`, в командной строке Windows — `cd` без аргументов. Если папка с таким именем уже существует, откройте её или выберите другое место — не удаляйте её для повторной установки.

В выводе `git remote -v` должен быть адрес вашей копии. Через действие открытия локальной папки/проекта в ИИ-клиенте выберите эту папку. В ней должны быть README.md, AGENTS.md и package.json.

Если Git ещё не настроен для коммитов, задайте имя и email **внутри папки проекта**, заменив примеры на свои данные:

```sh
git config user.name "Ваше имя"
git config user.email "Ваш email для коммитов"
```

Email для коммитов можно взять в **GitHub → меню аватара → Settings → Emails**, включая ваш адрес `noreply`, если используете его. Эти две команды задают подпись коммитов в данном проекте, а не выполняют вход в GitHub. Если имя и email уже настроены правильно, менять их не нужно.

## 7. Попросите агента подготовить проект

В чате открытого проекта напишите:

> Прочитай AGENTS.md и выполни dais-setup. Проверь программы, установи зависимости, настрой MCP, проверь его подключение и запусти приложение. Покажи адрес для браузера. Пока не публикуй.

Основная команда, которую выполнит агент:

```sh
npm run setup
```

Она устанавливает библиотечные зависимости и настраивает MCP, но не устанавливает Node, Git или сам ИИ-клиент. После неё один раз перезапустите агент в этой папке для подхвата MCP и навыков; при запросе разрешите подключение сервера `dais-ui`. Если навыки не появились, агент читает `.agents/skills/*/SKILL.md` напрямую. `mcp:check` проверяет сервер отдельно; подключение клиента подтверждается вызовом `get_component(TableCanvas)` самим агентом. Затем агент или вы запускаете:

```sh
npm run dev
```

Откройте напечатанный локальный адрес — обычно `http://localhost:5173`. Оставьте сервер работающим, пока смотрите макет. Для остановки нажмите `Ctrl+C` в его терминале. Успех: появилась галерея и открывается «Коллекция» с интерактивной таблицей.

## 8. Создавайте макеты и выбирайте результат

Прикрепите PNG и напишите: «Собери новый вариант по скриншоту на Dais UI, сохрани предыдущие макеты». Изменения, сделанные через саму таблицу, действуют до перезагрузки или выхода из варианта. Для другого постоянного начального состояния попросите агента изменить данные в коде.

При визуальной или интерактивной проблеме агент сначала воспроизводит её в браузере, затем проверяет результат. Для очевидной замены текста/данных снимки не обязательны. Связанные правки проверяются вместе; браузерные автотесты не запускаются.

**Чтобы передать файл**, напишите: «Собери прототип collection в один HTML без галереи». Результат — `dist-html/collection/index.html`, который можно переименовать и отправить. Получатель скачивает и открывает его в браузере. [Инструкция](HTML_EXPORT.md).

**Чтобы передать ссылку**, напишите:

> Проверь проект, настрой GitHub Pages для моего репозитория, опубликуй и дождись успешного GitHub Actions. Дай ссылку на приложение.

При первой публикации с gh агент выполняет `npm run publish:setup`; без gh откройте настройки Pages в браузере. Нужный источник: **Settings репозитория → Pages → Source: GitHub Actions**. В профиле отдельную услугу хостинга включать не нужно. Затем агент отправляет commit и проверяет публикацию. Подробные шаги, ручной вариант и картинки GitHub — в [инструкции публикации](PUBLISHING.md).

Коллегам отправляйте адрес Pages вида `https://YOUR_LOGIN.github.io/my-prototypes/#/collection`, а не localhost и не вкладку Actions. После настройки новые изменения в main публикуются автоматически после проверок.

## Если на каком-то шаге не получилось

| Что видите | Следующее действие |
| --- | --- |
| node/npm/git/gh не найдены после установки | Полностью перезапустите терминал и ИИ-клиент; повторите проверку версий. Затем проверьте соответствующий установщик/PATH с агентом |
| В PowerShell запрещён npm.ps1 | Используйте `npm.cmd` вместо `npm` или откройте `cmd`; изменение политики PowerShell не требуется |
| npm сообщает, что нет package.json | Вы не в папке проекта: перейдите в папку с README.md и package.json |
| gh показывает другой аккаунт | Попросите агента проверить активный аккаунт через `gh auth status` и выбрать нужный; не выходите без причины из всех аккаунтов |
| Repository not found / Permission denied | Проверьте адрес своей копии, аккаунт GitHub и его доступ; в организации может требоваться дополнительное разрешение администратора |
| Git просит имя/email | Выполните настройку из раздела 6 со своими данными |
| MCP не появился | Перезапустите клиент, разрешите подключение проекта, попросите выполнить `npm run mcp:check` и проверить доступ к инструменту в самом агенте |
| npm не скачивает пакеты | Передайте агенту текст ошибки; проверьте доступ к npm registry, не отключайте проверку сертификатов |
| Инсталлятор требует права администратора | Подтвердите штатный системный запрос, если имеете права, либо обратитесь в ИТ |
| Actions красный | Откройте неуспешный запуск и шаг, передайте агенту ошибку; ссылка на код не доказывает публикацию сайта |

Можно написать агенту: «Я на шаге N, получил такую ошибку: … Помоги завершить этот шаг». Присылайте текст ошибки без паролей и токенов. Инструкции для ОС сверены с официальными источниками; установщики на чистых macOS/Windows в рамках этой проверки не запускались.
