# Один прототип — один HTML

Экспорт собирает выбранный экран с его начальным состоянием, библиотечными зависимостями и шрифтами. Галерея и остальные варианты не подключаются. Получателю не нужны Node.js, npm, Git, MCP, CDN или сервер.

## Для дизайнера

Попросите: «Собери прототип collection в один автономный HTML без галереи».

```sh
npm run export:html -- collection
```

Результат — **`dist-html/collection/index.html`**. Передайте только этот файл; его можно переименовать. Получатель скачивает HTML и открывает в обычном браузере. Встроенный просмотрщик мессенджера может не выполнять JavaScript. Локальный путь file:// не является общей ссылкой.

Вместо collection укажите ID нужного варианта из `src/prototypes`. Если вариант всего один, `npm run export:html` выберет его автоматически. При нескольких вариантах без ID команда покажет список и завершится без сборки. Экспорт следующего варианта не удаляет предыдущие: каждый хранится в своей папке внутри dist-html и передаётся отдельным HTML.

Изменения посетителя живут в памяти и сбрасываются при перезагрузке. Для постоянного начального состояния измените код и повторите экспорт. Файл не содержит состояние текущей браузерной сессии.

## Как устроено

- Команда проверяет TypeScript, затем Vite собирает `src/standalone.tsx`. Виртуальный импорт разрешается только в `src/prototypes/<slug>/index.tsx`, без App и общего списка вариантов. Общие модули, которые экран сам импортирует, остаются его зависимостями: не подключайте к нему реестр всех прототипов.
- `vite-plugin-singlefile` встраивает код и стили. Проверка результата требует ровно один index.html в папке выбранного варианта. Обычная `npm run build` сохраняет галерею в dist.
- Исходные макеты находятся в `.references`, вне src/public и Git. Они не используются приложением; попытка включить их через импорт приводит к ошибке сборки. Не переносите исходный PNG в ресурсы интерфейса. Снимки проверки хранятся в `.local/checks`.
- Ресурсы интерфейса подключайте импортами, чтобы Vite мог их встроить. public/ в HTML-экспорт не копируется. Внешние картинки, API, iframe, worker, динамические запросы и жёстко заданные пути требуют адаптации и проверки; однофайловая сборка не превращает произвольную сетевую зависимость в автономную.
- SB Sans Text/Display 0.2.0 из `src/assets/fonts/` встроены как WOFF2/data URL. Сохранены все 16 начертаний; SOURCES.json содержит происхождение и контрольные суммы. Размер зависит от компонентов, ресурсов и шрифтов выбранного экрана; один TableCanvas может оставаться существенной частью файла. Исключение других вариантов не гарантирует фиксированного размера.
- Старый `dist-html/index.html`, оставшийся от экспорта всей галереи, не является новым результатом. Передавайте только путь, напечатанный текущей командой.

## Проверка

Браузерных автотестов и установки браузера в шаблоне нет. При изменении упаковки/ресурсов, проблеме открытия или запросе автономной проверки откройте итоговый HTML через file:// с отключённой сетью. Проверьте выбранный экран без галереи, шрифты и затронутые действия. Сборка не доказывает корректность взаимодействий или отсутствие сетевых обращений. Если браузер или отключение сети недоступны, агент сообщает это отдельно.

Для уже проверенного экрана при неизменной упаковке полный повтор сценариев при каждом экспорте не нужен. Итоговый ответ содержит выбранный вариант, путь, размер и фактически выполненные проверки. История проверок — в docs/VALIDATION.md; прежние проверки экспорта всей галереи не подтверждают новый механизм автоматически.
