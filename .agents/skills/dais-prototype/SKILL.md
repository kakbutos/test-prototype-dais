# Прототип из макета

Прочитай `AGENTS.md` до реализации. Если формат результата ещё не выбран, используй вопрос из AGENTS.md; известный выбор не переспрашивай. Пока пользователь выбирает, можно готовить локальный экран.

## Выбери место изменения

Новый PNG без указания существующего прототипа означает новый независимый экран: форма становится формой, таблица — таблицей. Выполни `npm run prototype:new -- <slug> "Название"`; команда создаёт пустой React-компонент в `src/prototypes/<slug>/index.tsx`. Существующие варианты сохраняй. Не используй «Коллекцию» как обязательную заготовку для произвольного экрана.

Если пользователь просит встроить форму/диалог/другой элемент в названный прототип, изменяй этот прототип и связывай элемент с его сценарием. Не создавай отдельную страницу вместо запрошенного встраивания. Уточняй место изменения только при неоднозначности. Изменение общего recipe затронет всех его потребителей: специфичную логику держи внутри целевого варианта или передавай через props.

## Сохрани и открой исходник

Сохрани доступное вложение в `.references/<slug>/source.png` вне `src` и `public`. При создании можно передать `--reference "/путь/макет.png"`. Для нескольких исходников сохраняй отдельные имена и отмечай, какой относится к экрану; не перезаписывай их скриншотами реализации. Итоговые снимки храни отдельно в `.local/checks/<slug>/`. `.references` исключена из Git; Vite отклоняет включение файлов оттуда в сборку. Не импортируй исходники в код и не копируй их в public. Изображения, которые действительно нужны интерфейсу, — отдельные ресурсы приложения.

Открой именно исходный PNG доступным инструментом клиента. До реализации кратко зафиксируй его путь, размер, видимые секции, поля, значения и состояния. Эта запись помогает навигации, но не заменяет изображение при сверке. Если клиент позволяет видеть вложение, но не сохранить его, сообщи об этом; не утверждай, что исходник сохранён. При потере доступа запроси исходник повторно или продолжай только по явно согласованному описанию, без утверждения о визуальном сходстве.

Сохраняй видимый состав и начальное состояние макета. Для интерактивности используй минимально необходимые допущения. Не добавляй без основания в PNG или запросе новые секции, вкладки, бейджи, подзаголовки, обязательность, каскадные блокировки или панели действий. Обрезанный край не доказывает наличие или отсутствие элементов за кадром. Существенные неизвестные детали называй; уточняй только то, что блокирует реализацию.

## Проверь API до написания экрана

Используй MCP `get_installation_guide`, `search_components`, `get_component`, `get_component_props` для выбранных компонентов. Для таблицы доступны `list_features`, `get_feature`, `get_feature_examples`, при необходимости `get_type`.

MCP помогает найти API, но примеры могут не соответствовать установленной версии или ссылаться на Storybook-хелперы. Проверь реальные экспорты, допустимые props и их значения в установленном пакете до использования. Типы установленной версии приоритетнее примеров MCP; спорную семантику проверяй по реализации пакета и в браузере. Не угадывай названия иконок и не делай вывод об отсутствии иконки по одному несуществующему имени. Короткая карта источников и особенностей: `docs/COMPONENTS.md`.

Если инструменты MCP недоступны в сессии, проверь настройки и `npm run mcp:check`, затем читай установленные `.d.ts` и самодостаточные примеры. Успех этой команды подтверждает сервер, а не подключение клиента. Не меняй библиотеку из-за недоступного MCP. Для табличной задачи можно использовать `src/recipes/Collection.tsx`; для формы подбирай компоненты формы. Сообщи, если API изучался по локальным пакетам без вызова MCP из сессии. Визуальная сверка выполняется отдельно от MCP.

## Собери на компонентах Dais

Используй публичные импорты `@daisforge/ui`, `@daisforge/ui/icons`, `@daisforge/ui/tokens`. TableCanvas нужен для табличной задачи; внутри его ячеек используй Canvas.*, а не DOM-кнопки. Поиск, группировку и редактирование добавляй по макету или запросу, а не во все экраны автоматически. У каждого заявленного действия должно быть наблюдаемое последствие. Состояние хранится в памяти; не добавляй localStorage/sessionStorage/backend.

Не переопределяй внутренние стили библиотечных компонентов. Вид и размер выбирай через поддерживаемые конкретным компонентом `view`, `size`, `appearance`, `width`, `fullWidth` и другие props. При необходимости допускается задать внешнюю ширину/высоту; расположение и отступы композиции задавай контейнеру.

Композицию оформляй через styled-components, цвета и фоны — токенами библиотеки вместо хардкода:

```tsx
import styled from 'styled-components';
import { surfaceSolidSecondary } from '@daisforge/ui/tokens';
const Layout = styled.main`
  background-color: ${surfaceSolidSecondary};
`;
```

Название иконки на макете вроде `16/fill/Download` помогает найти экспорт, но не гарантирует его имя: проверь установленный набор. Используй IconButton/EmbedIconButton или contentLeft/contentRight у Button. Обычно цвет наследуется от родителя:

```tsx
import { IconButton } from '@daisforge/ui';
import { IconDownload } from '@daisforge/ui/icons';
<IconButton view="secondary" size="s" aria-label="Скачать" onClick={download}>
  <IconDownload size="s" color="inherit" />
</IconButton>
```

Стиль `Body/BodyS N` сопоставляй с `<BodyS>` или `<Typography variant="BodyS">`. Используй типографику Dais: DsplL/M/S, H1–H5, TextL/M/S/XS, BodyL/M/S/XS/XXS, проверяя доступность выбранного варианта. У библиотечных текстовых слотов уже есть оформление: передавай компонент типографики вместо строки только если сверка показывает необходимость. Не заменяй типографику произвольными font-size/font-weight ради похожего вида.

## Проверь результат

Во время правок используй dev-сервер, после набора изменений — `npm run typecheck`. Полная сборка нужна для экспорта/публикации. Следуй соразмерной проверке из AGENTS.md: воспроизведи визуальную/интерактивную проблему до исправления, после правок проверь затронутые действия и оцени итоговый скриншот. Для нового экрана открой исходный PNG и итоговый снимок, сравни состав, порядок, состояния, размеры, типографику, иконки и обрезание. Проверяй как недостающие, так и лишние элементы.

Сопоставляй область прототипа с областью PNG. Для просмотра без оболочки галереи используй `/?standalone=1#/<slug>`; размер окна подбирай по исходнику, если он представляет полный экран. Для фрагмента сравнивай соответствующую область. Не закладывай постоянную высоту шапки галереи. В HTML-экспорте оболочки уже нет.

Не пиши и не устанавливай браузерные автотесты автоматически. Снимок недостаточен для проверки поведения, а успешная сборка/клики не доказывают сходство с PNG. Если браузер или исходник недоступен, опиши границу проверки. Не называй результат точной копией без визуальной сверки.

В итоговом ответе дай адрес варианта и кратко раздели: внешний вид (исходник, размер области, оставшиеся расхождения), поведение (проверенные действия), технические проверки (что запускалось). Назови непроверенное; достаточно нескольких строк без большого чеклиста.

Для постоянного начального состояния меняй код. Для передачи используй выбранный dais-export-html или dais-publish; создание экрана само по себе не означает публикацию.
